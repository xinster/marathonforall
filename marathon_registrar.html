关于「自动提交报名」—— 为什么不做,以及我做了什么替代方案。 这不是偷懒,是技术上和合规上都走不通的路:

三道硬墙

障碍具体情况对「自动提交」的影响
实名认证 中国大陆赛事必须绑定身份证做实名核验;境外赛事需要护照信息与支付通道绑定。部分赛事还要求人脸识别。 无法在无人参与的情况下完成身份核验
验证码 / 风控 图形验证码、滑块验证、短信验证码、设备指纹。这是赛事组委会专门用来拦截机器人的设计。 绕过它等于违反赛事服务条款,账号会被封禁、名额会被取消
抽签制 中国绝大多数赛事(上马、北马、广马、福马…)和所有大满贯都是「预报名 → 抽签 → 中签 → 缴费」。
报名先后顺序完全不影响中签率。		 「抢在开放瞬间提交」这件事本身就是伪需求 —— 只有少数先到先得的赛事例外

真正会丢名额的环节,不是「没抢到报名」,而是「中签后忘记缴费」。 例如 2027 渣打香港马拉松:第一轮中签者只有 7 天付款期(9/25–10/2),第二轮只有 3 天(10/7–10/10)。 绝大多数被释放的名额,都死在这个环节上 —— 这才是本系统重点盯防的对象。

所以本系统做的是这四件事

能力说明
窗口监控对每场赛事实时计算状态:未开放 / 即将开放 / 报名中 / 即将截止 / 待抽签 / 待缴费 / 已截止,并给出倒计时与紧迫度排序。
资料一键就绪档案一次填好,任意赛事页一键复制「报名资料块」,直接粘贴进表单。
截止前主动提醒导出 .ics 日历事件到手机(报名开放日、截止日、抽签日、缴费截止日、比赛日),或由每日自动化任务发邮件告警。
材料清单核验按赛事规则生成所需材料清单(参赛经历、体检报告有效期、直通资格),缺项在卡片上直接标红。

如果确实需要「半自动填表」,可以配合浏览器自动化工具打开报名页帮你把能填的都填上, 但最后一步的验证码和「提交」按钮,仍然需要你本人点击 —— 这一步不该被自动化,也不该被自动化。

数据管理

所有数据只存在这台设备的浏览器本地存储里,不上传任何服务器。 导出的 .json 可以交给每日自动化任务,由它扫描窗口变化并给你发邮件告警。 建议同时另存一份到 data/ 目录做备份。
