# legacy/ · 历史产物

这两个文件**不是产品的一部分**,留在仓库里有各自不同的理由。**先读完再决定动谁。**

## `marathon_registrar.html`(77KB)

第一版**单文件指挥中心**:把状态机、界面、档案、材料清单全塞进一个 HTML 里。
产品已经演进成 `marathon-platform/`,这个文件不再更新。

### ⚠️ 但它不能删 —— 它是防漂移测试的对照基线

`tests/regression.js` 的第 A 段「引擎防漂移」**要把这个文件里的旧状态机抽出来**,
当成对照基准,用来证明平台版引擎没有把路跑 24 场的状态判断改坏
(那一段跑了 1152 组对照)。

抽取方式是按**行号切片**:

```js
const js = html.split("<script>")[1].split("</script>")[0].split("\n");
const sl = (a, b) => js.slice(a - 1, b).join("\n");
// 抽 sl(10,33) + sl(59,243) + sl(278,284) + sl(286,362)
```

**所以这个文件一改格式,切片就会错位。**

已加守卫断言:切片必须能抽出 24 场路跑且 `computeStatus` 可用,
否则测试直接以退出码 3 终止,不会拿坏数据比对得出「零漂移」的假绿。

> **改了这个文件 → 一定要重跑 `node tests/regression.js`。**
> 如果守卫失败,对照上面那几个行号区间更新 `sl()` 的取值。

### 什么时候可以删

把当前基线**冻结成一份 JSON 快照**(每个赛事 × 每个 `userStatus` × 每个时间点的预期状态),
测试改成读快照 —— 那时这个文件就退化回纯历史,可以删。见 `docs/HANDOVER.md` 待办。

## `marathon_calendar_2026.html`(44KB)

最开始的产物:162 场全球路跑赛历,分十月 / 十一月 / 十二月三张表,带地区筛选。

**没有任何代码引用它。** 留档是因为里面的日期锚点(各赛事的常规举办周次、
中国「超级周日」的撞车规律)在人工核对新赛历时还有参考价值。

### ⚠️ 但它不是数据源

里面的日期是 **2026-10-06 那次检索的结果**,不是活数据。赛事的权威数据在
`marathon-platform/assets/engine.js` 的 `SEED_*` 里。**不要从这里抄日期。**
